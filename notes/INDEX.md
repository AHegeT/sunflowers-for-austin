## How to use the notes

The files in `../manuscript/` are the repository reading drafts. Notes describe context, plans, experiments, and alternative versions. Google Docs pointers are retained; no Docs contents have been fetched or compared during this organization pass. If a Docs draft is newer, reconcile it explicitly with the repository draft before treating either as the final version.

Keep factual status separate from filing location. When reviewing a note, mark individual sections as **established in manuscript**, **planned**, **possible**, **superseded**, or **open question**, and link to the evidence. A mixed note can contain more than one status. Dates are useful context, but a newer suggestion does not automatically supersede an older decision. AI-generated text and transcript summaries also require author review.

Existing filenames were preserved so basename Obsidian links continue to resolve. Prefer standard relative Markdown links in new indexes so they work in VS Code and GitHub too. The old hub still contains Dataview queries and links to the broader vault; [the catalogue](CATALOGUE.md#links-to-the-original-vault) records those limitations. Open `notes/` as an Obsidian vault if you want to use the same files in both editors.

Recordings, raw text, alternate drafts, empty placeholders, and the original archive were retained. Do not replace a recording’s raw source with an edited summary, and do not delete a draft merely because a similar scene exists in the manuscript.
